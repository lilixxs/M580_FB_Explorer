# M580_FB_Explorer 도움말

이 페이지는 브라우저에서 Control Expert 교환 파일을 분석합니다. 가져온 파일을 업로드하지 않습니다. PLC에 연결하지 않습니다.

이 문서의 스크린샷은 내장 예제만 사용합니다.

## 1. 인터페이스 언어

상단 표시줄에 언어 전환 항목이 있습니다. 간체 중국어, 영어, 번체 중국어, 일본어, 한국어 중에서 선택할 수 있습니다.

브라우저가 로컬 저장소를 허용하면 페이지가 언어 선택을 기억합니다.

언어를 전환해도 문서, 소스 코드, 아직 내보내지 않은 변경 사항은 사라지지 않습니다.

인터페이스 표시와 메시지는 선택한 언어를 사용합니다. PLC 식별자, 사용자 파일 내용, XML 형식 값은 인터페이스 언어와 무관하게 유지됩니다.

기존 상태 메시지와 분석 경고는 생성 당시의 언어를 유지합니다. 이후 작업은 새로 선택한 언어를 사용합니다.

## 2. 파일 가져오기

![작업 공간](images/ko/workspace.png)

상단 표시줄의 "파일 가져오기"를 클릭하여 .xdb, .xst, .xsy 파일을 선택합니다. 파일을 창에 끌어다 놓을 수도 있습니다.

상단 표시줄의 예제 단추를 클릭하면 내장 예제를 불러옵니다.

가져오기와 내보내기 단추는 상단 표시줄에만 있습니다. 왼쪽 위 패널에는 가져오기와 내보내기 단추가 없습니다.

왼쪽 위 영역에 파일 정보, 섹션 목록, 분석 경고 항목이 표시됩니다.

섹션을 클릭하면 오른쪽 아래 에디터에 해당 내용이 표시됩니다.

한 번에 하나의 문서만 편집합니다. 다시 가져오면 현재 문서를 대체합니다. 변경된 파일을 먼저 내보내세요.

가져오기에 성공하면 페이지는 검색어와 접힘 상태를 지웁니다.

페이지는 단일 FBSource의 .xdb 파일, 섹션 .xst 파일, 변수 표 .xsy 파일을 지원합니다. 여러 기능 블록 범위는 아직 합쳐지지 않습니다. 안전하게 처리할 수 없는 구조는 가져오기를 거부하고 이유를 표시합니다.

ST가 아닌 섹션은 읽기 전용 XML 원문을 표시합니다. 페이지는 도표 언어를 ST로 변환하지 않습니다.

## 3. 기능 블록 새로 만들기

![기능 블록 새로 만들기](images/ko/new-block.png)

상단 표시줄의 "기능 블록 새로 만들기"를 클릭하면 대화 상자가 열립니다.

대화 상자에서 기능 블록 이름을 입력합니다. 주석도 입력할 수 있습니다.

이름은 이 프로젝트의 IEC 식별자 규칙을 따라야 합니다.

확인하면 페이지는 빈 변수 표와 빈 ST 섹션 하나를 만듭니다.

현재 문서에 아직 내보내지 않은 변경 사항이 있으면, 페이지는 대체하기 전에 확인을 요청합니다.

새 문서는 기존 변수 편집, ST 편집, 저장, .xdb 내보내기 절차를 사용합니다.

## 4. 메타 정보 편집

기능 블록 이름과 주석은 초안 편집을 사용합니다.

새 값을 입력한 뒤 "확인"을 클릭해야 문서에 기록됩니다.

"취소"를 클릭하면 이전 값으로 돌아갑니다.

## 5. 레이아웃 및 핀 보기

왼쪽 열과 오른쪽 열은 기본적으로 34%와 66%입니다. 오른쪽 위 변수 목록은 기본적으로 높이의 1/3, 오른쪽 아래 섹션 에디터는 기본적으로 높이의 2/3입니다.

왼쪽 열에는 메타 정보, 호출 목록, 핀 호출 보기가 순서대로 표시됩니다. 구분 막대를 끌면 패널 크기를 조절합니다. 구분 막대를 더블 클릭하면 크기가 초기화됩니다. 구분 막대에 초점을 맞춘 뒤 방향키로 세밀하게 조절합니다.

페이지는 좁은 화면에서 세로 배치로 전환됩니다. 패널 안의 표는 가로 스크롤을 지원합니다. 브라우저가 로컬 저장소를 허용하면 페이지는 패널 크기를 기록합니다.

핀 보기에는 IN, OUT, IN_OUT이 표시됩니다. IN_OUT은 파선으로 표시합니다. PRIVATE, PUBLIC, GLOBAL은 핀으로 그려지지 않습니다. EN과 ENO는 시스템 핀 표시일 뿐입니다. 핀을 클릭하면 오른쪽 위 목록에서 변수를 찾습니다.

핀 패널의 더하기와 빼기 단추로 보기를 확대하거나 축소합니다. 핀을 클릭하면 페이지는 변수 검색어를 지우고 해당 그룹을 펼칩니다.

핀 또는 변수 행을 클릭하면 에디터가 해당 변수의 사용 위치를 찾습니다. 호출 패널은 관련 변수 참조를 표시합니다. 참조가 없는 변수는 무관한 이동을 발생시키지 않습니다.

## 6. 변수 관리

![변수 에디터](images/ko/variable-editor.png)

변수는 IN, OUT, IN_OUT, PUBLIC, PRIVATE, GLOBAL별로 그룹화합니다. GLOBAL은 dataBlock 전역 변수에 해당합니다.

검색 상자에 변수 이름, 형식, 주소, 초깃값, 주석을 입력합니다. 검색하면 일치하는 그룹이 자동으로 펼쳐집니다. 그룹 제목을 클릭하면 그룹을 접습니다.

"추가"를 클릭하면 변수를 만듭니다. "수정"을 클릭하면 변수를 바꿉니다. "삭제"를 클릭하고 확인하면 변수를 제거합니다. 위아래 화살표로 같은 종류 변수의 순서를 조절합니다. 핀 번호 PositionPin은 순서대로 다시 계산됩니다.

![형식 선택](images/ko/type-picker.png)

"형식 선택"을 클릭하면 기본 형식을 선택할 수 있습니다. 사용자 지정 형식도 입력할 수 있습니다. 배열 모드는 요소 형식, 하한, 상한을 제공합니다. 결과는 ARRAY[하한..상한] OF 형식 형식을 사용합니다.

변수 표에는 형식과 주소를 따로 표시합니다. 변수 표를 스크롤하면 현재 그룹 제목이 표 위쪽에 고정됩니다.

변수 이름은 영문자나 밑줄로 시작해야 합니다. 나머지 문자는 영문자, 숫자, 밑줄만 허용합니다. 변수 이름은 대소문자를 구분하지 않고 중복될 수 없습니다. EN과 ENO는 일반 핀으로 추가할 수 없습니다.

32비트 형식은 %MW에 바인딩할 때 짝수 주소를 사용해야 합니다. 페이지는 임의로 주소를 바꾸지 않습니다. 잘못된 주소는 변수 대화 상자에서 수정하세요.

## 7. ST 호출 분석

![호출 브라우저](images/ko/call-browser.png)

왼쪽 가운데 목록에 함수와 기능 블록 호출이 표시됩니다. 목록은 알 수 없는 호출을 유지하며, 알 수 없는 이름을 시스템 함수로 보지 않습니다. 파서는 문자열과 주석 안의 가짜 호출을 무시합니다.

호출 항목을 클릭하면 에디터가 해당 행과 열로 이동합니다. "다시 분석"을 클릭하면 코드를 다시 분석합니다. 섹션을 저장해도 호출 목록이 갱신됩니다.

호출 패널은 일반 변수 참조도 제공합니다. 참조 분석은 주석, 문자열, 명명 인자의 형식 매개변수 이름을 무시합니다. 참조를 클릭하면 코드, 변수 행, 해당 핀을 동시에 찾습니다. 에디터에서 변수를 클릭하면 선택 상태도 갱신됩니다.

호출 분석은 구문 컴파일이 아닙니다. 페이지는 모든 함수 시그니처를 검사하지 않으며, ST 코드를 실행하지 않습니다.

## 8. 에디터 작업

| 작업 | 진입점 |
| --- | --- |
| 찾기 | Ctrl+F, 도구 모음, 상황에 맞는 메뉴 |
| 바꾸기 | Ctrl+H, 도구 모음, 상황에 맞는 메뉴 |
| 행:열 이동 | Ctrl+G 또는 행:열 입력 상자 |
| 서식 지정 | Shift+Alt+F, 도구 모음, 상황에 맞는 메뉴 |
| IF / FOR / WHILE 삽입 | 도구 모음, 상황에 맞는 메뉴 |
| 함수/기능 블록 호출 | 도구 모음, 상황에 맞는 메뉴 |
| 저장 및 분석 | Ctrl+S 또는 저장 단추 |
| 자동 완성 | 입력 중, 또는 Ctrl+Space |

자동 완성에는 키워드, 현재 변수, 자주 쓰는 함수, 문장 템플릿이 포함됩니다. 서식 지정기는 지원되는 ST 구조만 정리합니다. 완전한 IEC 61131-3 컴파일러를 대신하지 않습니다.

에디터의 저장은 페이지 메모리에 기록할 뿐입니다. 저장은 디스크의 원본 파일을 바꾸지 않습니다. 변경된 파일을 내려받으려면 상단 표시줄의 ".xdb 내보내기"를 클릭하세요.

저장 후 다시 분석하면 현재 섹션의 "저장 안 함" 표시가 사라집니다. 상단 표시줄의 "변경 있음"은 아직 내보내지 않았다는 뜻입니다. 섹션을 저장해도 사라지지 않습니다.

"함수/기능 블록 호출" 대화 상자는 분류 열과 항목 열로 구성됩니다. 대화 상자는 검색, 함수, 기능 블록, 현재 문서의 섹션, 사용자 지정 호출을 지원합니다. 삽입 위치는 대화 상자를 열 때의 에디터 선택 영역 또는 커서입니다.

EFB는 인스턴스를 사용해야 합니다. 같은 종류의 기존 인스턴스를 선택하거나, 새 인스턴스 이름을 입력하고 PRIVATE 변수 생성을 확인한 뒤 삽입합니다. 삽입 후 매개변수와 호출 위치를 확인하세요. 섹션 이름 호출은 모든 작업 맥락에 맞음을 보장하지 않습니다.

함수와 변수 형식 데이터는 src/data/functionLibraries/ 아래 JSON에서 가져옵니다. 기본 스냅숏은 공식 매뉴얼 전체가 아닙니다. 각 라이브러리는 출처와 범위를 명시합니다. 유지 관리 방법은 저장소의 CONTRIBUTE.md를 참조하세요. JSON을 바꾼 뒤에는 다시 빌드해야 합니다.

Standard 라이브러리 자료는 33002519.20(09/2020, Control Expert 15.0 이상 대상)에서 나옵니다. 카탈로그는 별도로 보관합니다. 호출 목록은 검증된 구체 함수만 포함합니다. 변수 형식 설명은 35006144.27에서 나옵니다. 이전 프리셋의 확장 형식은 M580 지원이 검증됨을 뜻하지 않습니다. Unity Pro V13.1 호환성은 검증되지 않았습니다.

Monaco를 불러오지 못하면 페이지는 오류를 표시하고 텍스트 상자로 전환합니다. 텍스트 상자는 구문 강조와 자동 완성을 제공하지 않습니다.

## 9. 내보내기 규칙

내보내기 도구는 저장소 AGENTS.md의 4절에 따라 XML을 생성합니다.

- STSource는 실행 문장만 허용합니다. VAR 선언 영역을 감지하면 페이지는 내보내기를 거부합니다. 변수는 변수 표에 넣으세요.
- 입력, 출력, 양방향 매개변수는 해당 컨테이너에 기록합니다. PositionPin은 1부터 증가합니다.
- 기능 블록 초깃값은 variableInit에 기록합니다. 전역 변수 초깃값은 defaultValue에서 읽습니다.
- 빈 topologicalAddress와 빈 comment는 생략합니다.
- 내보내기 도구는 자기 닫힘 태그를 펼칩니다.
- 32비트 %MW 변수는 짝수 주소에 바인딩해야 합니다. 검증이 실패하면 내보내기를 거부합니다.
- .xdb를 다시 쓸 때 편집하지 않은 확장 노드와 속성을 유지합니다.

.xst 또는 .xsy에서 .xdb로 내보내기는 구조 변환입니다. GLOBAL 변수는 PRIVATE로 바뀝니다. 페이지는 변환 경고를 표시합니다. 섹션의 작업 맥락이 PLC 작업이 되지는 않습니다. 변환 결과를 확인하세요.

내보내기에 경고가 포함되면 페이지는 "내보내기 설명" 서랍에 경고 전체를 표시합니다.

Control Expert 가져오기, 컴파일, 실기 통신 테스트는 모두 실행되지 않았습니다.

## 10. MCP 예약 인터페이스

페이지는 window.__M580_MCP_BRIDGE__를 제공합니다. 브리지는 listTools(), callTool(name, input), getState()를 제공합니다.

이는 페이지 안의 도구 인터페이스이며, 독립적인 MCP 서버가 아닙니다. 페이지는 기본적으로 원격 서비스에 연결하지 않습니다. 전송 어댑터는 연결 경계만 제공합니다.

| 도구 | 용도 |
| --- | --- |
| m580_fb_get_metadata | 문서 요약을 읽습니다 |
| m580_fb_list_variables | category와 search로 변수를 조회합니다 |
| m580_fb_upsert_variable | id로 변수를 바꾸거나 변수를 추가합니다 |
| m580_fb_delete_variable | id로 변수를 삭제합니다 |
| m580_fb_get_source | sectionId로 코드를 읽습니다 |
| m580_fb_set_source | source를 기록하고 호출을 분석합니다 |
| m580_fb_insert_snippet | line, column 위치에 source 또는 kind 템플릿을 삽입합니다 |
| m580_fb_analyze_calls | 호출을 다시 추출합니다 |

호환 도구로 다음을 유지합니다: m580_get_state, m580_import, m580_list_variables, m580_upsert_variable, m580_delete_variable, m580_get_section, m580_set_section_source, m580_save_section, m580_format_section, m580_replace_in_section, m580_extract_calls, m580_export_xdb, m580_get_help, m580_jump.

각 도구의 필드와 필수 매개변수는 listTools()가 반환하는 inputSchema를 확인하세요. callTool()은 ok, result, error를 반환합니다.

예:

```js
await window.__M580_MCP_BRIDGE__.callTool('m580_fb_list_variables', { category: 'IN' })
```

## 11. 배포 및 업데이트

npm run build를 실행한 뒤 dist/ 전체를 정적 파일 서버에 복사합니다. 하위 경로 배포를 지원합니다. file://로 직접 열지 마세요. Monaco 워커는 HTTP 또는 HTTPS로 불러와야 합니다.

빌드 산출물에는 페이지, 스타일, 스크립트, 워커가 포함됩니다. 빌드 산출물은 외부 CDN에 의존하지 않습니다.

도움말의 진본은 requirements/localization/help/ 아래의 zh-CN.md, en.md, zh-TW.md, ja.md, ko.md입니다. 앱은 선택한 언어의 .md를 Vite raw로 불러옵니다. 빌드는 도움말 파일을 dist/HELP.{locale}.md로 복사하고 기본 HELP.md를 생성합니다. README.md는 README.en.md의 복사본에서 생성됩니다.

기능이 바뀔 때마다 도움말 문서와 docs/requirements.md를 갱신해야 합니다. 배포할 때마다 형식 검사, 단위 테스트, 빌드를 다시 실행해야 합니다.
